# 아키텍처 결정 기록 (ADR)

중요한 결정의 맥락과 근거, 그리고 **기각한 대안**을 남긴다.

"무엇을 정했는가"는 [로드맵](../roadmap.md)에 있다.
여기에는 **왜 그렇게 정했고 무엇을 버렸는가**가 있다.

## 규칙

- **이미 쓴 ADR은 고치지 않는다.** 오타 수정만 예외다.
- 결정이 바뀌면 새 ADR을 쓰고, 기존 ADR의 상태를 `대체됨`으로 바꾸면서 대체한 번호를
  적는다. 판단의 역사가 남아야 한다.
- 번호는 4자리 일련번호다. 한 번 부여하면 재사용하지 않는다.
- 상태는 `제안됨` · `채택` · `대체됨` · `폐기` 중 하나다.
- 제목은 명사형으로 끝낸다. [개발 규약](../conventions.md#커밋-메시지)과 같은 기준이다.

## 형식

배경 → 결정 → 근거 → 기각한 대안 → 결과.

**기각한 대안이 가장 중요하다.** 그것이 없으면 ADR을 쓸 이유가 없다.
결정만 적을 거라면 로드맵으로 충분하다.
